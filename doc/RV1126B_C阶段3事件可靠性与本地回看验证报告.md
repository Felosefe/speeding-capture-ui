## 1. 阶段交付

- 新增 `EventViewController`，只通过 `IEventRepository`、`EventSyncService` 和 `EvidenceCache`
  编排事件展示，不直接访问 SQL、HTTP reply 或板端路径。
- `IEventRepository` 增加按复合身份精确加载和删除接口；`EvidenceCache` 增加异步删除本地 evidence
  接口。删除顺序固定为先图片、后事件，图片失败时保留事件记录。
- 改造现有抓拍表模型为双数据源：`--mock` 保留 `CaptureRecord`，真实模式使用完整
  `VehicleEvent`，以 `(device_id,event_id,track_id)` 原行 upsert。
- 主界面增加实时事件/本地历史、当前设备/全部设备、车牌和可选时间范围筛选，以及每页 100 条的
  本地分页。
- 正式事件列增加 OCR、速度、时间质量和 evidence 缓存状态。`board_epoch_unverified` 使用警告色和
  tooltip 明确说明不可作为可靠 UTC。
- 抓拍预览支持 PC 本地 JPEG 解码和等比例显示；在线缺图触发缓存，离线未缓存、处理中/重试、失败
  和损坏文件均有独立提示。
- 真实历史支持按当前筛选遍历全部分页导出 UTF-8 CSV；支持本地单条删除和筛选范围清空，并明确
  提示板端事件可能再次同步。

## 2. 生命周期与可靠性规则

- `eventChanged` 后按完整 `EventIdentity` 精确读取仓储，queued 更新为终态时不产生第二行；未知 OCR
  状态不擅自归类为终态。
- 暂停刷新只冻结 UI。事件同步、SQLite upsert 和 evidence 缓存继续运行，恢复时重新查询仓储。
- evidence 状态为 Available 但正式文件不存在时不伪装成功；设备在线则重新排队下载，离线则显示
  未缓存。
- 清空历史期间临时停止匹配设备的同步服务，逐条删除图片和事件后恢复原先运行的同步服务；删除
  失败记录继续保留。
- 设备断开先停止该设备同步、取消仓储请求和图片任务，再由阶段 2 控制器停止 RTSP 和 fleet 会话。
- 应用退出停止全部同步、取消 repository 和 cache 任务，再关闭扫描、RTSP 和数据会话；普通断开和
  退出不删除 SQLite 或正式 JPEG。

## 4. A/B 合入要求与真机待办

当前默认真实模式仍未装配 A/B 生产服务，因此事件区域会明确提示不可用，RTSP 和 `--mock` 不受影响。
A/B 合入时需要：

1. 实现新增的 `IEventRepository::loadEvent/deleteEvent` 和 `EvidenceCache::removeLocal`。
2. 在装配层注入 repository、cache，并为每个设备动态挂接一个 `EventSyncService`。
3. 真机验证同一事件 queued 到终态只保留一行，Qt 断线期间事件可通过 cursor 分页补齐。
4. 验证 evidence 经过 `.part`、长度/JPEG 校验和原子改名后可离线回看。
5. 验证设备断开和应用退出后无残留轮询、repository completion、下载任务、`.part` 或媒体资源。

只有上述真机记录完成后才能关闭整个阶段 3 G3；本报告只关闭软件 C 可独立完成的交付项。
