# RV1126B Qt B 任务实现计划

版本：v1.0  
日期：2026-07-17  
负责人方向：软件 B，事件数据与本地存储  
适用工程：`D:\CameraManagerApp`，分支 `feature/rv1126b`

## 1. 目标

B 任务负责 RV1126B 接入中的数据闭环：

```text
HTTP 事件页/详情 -> 事件标准化 -> SQLite 持久化
                  -> 非终态事件刷新 -> 断线补齐
                  -> evidence 图片缓存 -> 本地历史回看
                  -> FTP 任务快照 -> 自动化测试
```

本任务不直接实现 UDP 发现、HTTP 客户端、RTSP 播放器或 UI 页面，但需要向 A 和 C 提供稳定的数据接口。

## 2. 当前基线

仓库已经具备以下基础：

- `src/rv1126b/domain/Models.h`：正式领域模型。
- `src/rv1126b/ports/IEventRepository.h`：B 侧 repository 抽象接口。
- `src/rv1126b/services/EventSyncService.h`：事件同步服务抽象接口。
- `src/rv1126b/services/EvidenceCache.h`：图片缓存服务抽象接口。
- `src/rv1126b/ports/IBoardApiClient.h`：A 侧网络接口，B 后续只通过它获取板端数据。
- `Rv1126bArchitectureTypesTest`：架构类型与抽象接口冻结测试。

当前缺口：

- 没有正式 RV1126B SQLite schema。
- 没有 `IEventRepository` 的 SQLite 实现。
- 没有事件同步、断线补齐和 evidence 缓存实现。
- 没有 B 侧自动化测试覆盖。

## 3. 模块拆解

### B1. SQLite schema 与迁移

对应任务：`BAS-04`、`DAT-01`

交付内容：

- 建立正式数据库文件，默认建议为 `data/rv1126b_events.sqlite`。
- 使用 `PRAGMA user_version` 管理 schema 版本。
- 建表：
  - `rv_devices`
  - `rv_events`
  - `rv_event_details`
  - `rv_evidence_cache`
  - `rv_sync_anchors`
  - `rv_ftp_tasks`
  - `rv_ftp_task_targets`
- 核心唯一键：
  - 事件：`(device_id, event_id, track_id)`
  - evidence：`(device_id, event_id, track_id, role)`
  - FTP target 状态：`(device_id, task_id, target_id)`
- 建立常用索引：
  - 按设备和时间查询历史。
  - 按车牌查询历史。
  - 按非终态 OCR 状态查询待刷新事件。
  - 按 evidence 缓存状态查询待下载/失败记录。

验收标准：

- 空库可初始化。
- 重复初始化幂等。
- schema version 可读取。
- 旧库后续可通过迁移函数升级。

### B2. `SqliteEventRepository`

对应任务：`DAT-02`

交付内容：

- 新增 `rv1126b::SqliteEventRepository`，实现 `IEventRepository`。
- 支持：
  - `initialize`
  - `upsertDevice`
  - `loadDeviceProfiles`
  - `upsertEvents`
  - `saveDetail`
  - `queryEvents`
  - `loadNonTerminalEvents`
  - `saveEvidenceState`
  - `loadEvidenceState`
  - `loadSyncAnchor`
  - `saveSyncAnchor`
  - `saveFtpTaskSnapshot`
- 所有写入使用事务。
- 同一事件状态变化时更新原记录，不重复插入。
- 所有 JSON 扩展字段保存为 compact JSON 字符串。

验收标准：

- 复合键 upsert 正确。
- queued 事件更新为终态后仍只有一条记录。
- 分页查询顺序稳定。
- 非终态事件可单独查询。

### B3. `EventSyncService` 正式实现

对应任务：`DAT-03`

交付内容：

- 新增事件同步服务实现，通过 `IBoardApiClient` 拉取事件页。
- 支持可配置轮询间隔。
- 请求未完成时不堆积下一次同类请求。
- 首屏轮询结果写入 repository。
- 非终态事件触发详情刷新。
- 对错误码、超时、取消和网络失败做退避。

验收标准：

- mock client 下可稳定轮询。
- 事件更新后发出 `eventChanged`。
- A 侧网络失败不破坏本地数据。

### B4. 断线补齐

对应任务：`DAT-04`

交付内容：

- 重连后读取 `SyncAnchor`。
- 从板端分页向后补齐，直到遇到本地连续边界或服务端结束。
- 对本地非终态事件单独刷新详情。
- cursor 只作为补齐过程状态，不作为永久订阅游标。

验收标准：

- Qt 离线期间生成、且仍在板端保留期内的事件可补齐。
- 补齐过程可中断并重试。

### B5. `EvidenceCache`

对应任务：`DAT-05`

交付内容：

- 后台下载 evidence 图片。
- 每设备最多 1 个下载，全局最多 4 个下载。
- 使用 `.part` 临时文件。
- 校验：
  - HTTP 成功状态。
  - `Content-Length` 与实际接收字节。
  - JPEG 可解码性。
- 校验通过后同目录原子重命名。
- 失败状态写入 repository。
- 409/临时失败进入退避重试。

验收标准：

- 中断不会留下伪装成成功图片的半文件。
- 本地已有图片时不重复下载。
- 离线历史可正确显示缓存状态。

### B6. 本地历史与缓存策略

对应任务：`DAT-06`

交付内容：

- C 侧历史界面优先使用本地图片。
- 在线时自动补下载缺失图片。
- 离线且无缓存时返回明确状态。
- 接入系统设置中的保留天数、容量阈值和清理策略。

验收标准：

- 本地历史不依赖设备在线。
- 清理策略不删除仍在下载中的 `.part` 文件。

### B7. 自动化测试

## 6. 风险与约束

- 当前本机 Qt 是 `D:\QT\6.8.3`，仓库预设指向 `C:\Qt\6.11.1`；本地验证时需要使用本机专用构建目录或后续统一环境。
- B 侧不能绕过 A 的 `IBoardApiClient` 直接拼 HTTP URL。
- B 侧不能让 UI 直接访问 SQL。
- 所有事件写入必须以 `(device_id,event_id,track_id)` 为准，不能退回单字符串 id。
- JSON 原文和未知字段必须保留，避免协议扩展时丢数据。
