## 1. 阶段交付

- 新增无 QWidget 依赖的 `DeviceIntegrationController`，通过既有抽象接口注入发现、fleet、凭据和
  RTSP 播放器，不重复实现软件 A/B 的 UDP、HTTP、SQLite 或事件同步职责。
- 新增设备搜索/连接对话框，支持扫描状态、按 `device_id` 去重、重复发现更新 IPv4、Bearer Token
  密码输入、credential 引用复用和认证失败提示。
- 主界面真实模式嵌入 `IRtspPlayer::outputWidget()`；连接成功后默认播放辅码流 `/live/1`，允许切换
  主码流 `/live/0`。
- 默认运行真实设备模式，不再静默创建模拟设备；原模拟设备和模拟抓拍通过 `--mock` 显式保留。
- 设备表新增连接中、在线、退化、认证失败、断开中和离线状态，并以 `device_id` 作为稳定身份。

## 2. 状态与生命周期规则

- 仅当 health 会话进入 `Online` 后打开 RTSP；初始 URL 由设备 IPv4 派生为
  `rtsp://<device-ip>/live/1`，不包含 HTTP Token、用户信息或查询参数。
- HTTP 会话进入 `Degraded` 时不停止已经运行的 RTSP；RTSP 错误只更新播放状态，不修改 HTTP
  会话状态。
- 切换视频设备时先停止旧 RTSP，再打开新设备当前码流；不调用旧设备的数据会话断开。
- `AuthenticationFailed` 停止当前视频并提示“认证失败，请重新配置 Token”；相同失败状态重复通知
  不重复弹出提示，也不自动重新提交错误 Token。
- 用户断开当前设备时先停止 RTSP，再调用 fleet 断开；退出时取消扫描、停止视频并断开全部 PC 数据
  会话。SQLite 和正式 evidence 文件不在该流程中删除。
- 扫描使用 request id 隔离代次，取消或重新扫描后忽略旧扫描的迟到数据。

## 3. 凭据处理

- Token 输入框使用密码回显模式，提交后立即清空。
- Token 仅以临时字节缓冲传入 move-only `SecretValue`，随后交给 `ISecretStore`；设备模型只保存
  `credentialRef`。
- Token 不写入 SQLite、QSettings、设备表、RTSP URL、测试快照或普通错误文本。
- 已存在 credential 引用时允许输入留空；新设备声明 `auth_required=true` 且没有引用时拒绝空 Token。

- 搜索启动、取消、按身份去重、IPv4 更新和迟到响应隔离。

- HTTP 退化不停止视频、RTSP 失败不覆盖会话状态。

## 5. 真机联合验收待办

当前分支只有 A/B 冻结的抽象接口，没有具体 `DeviceDiscoveryService`、`DeviceFleetService`、
`ISecretStore` 生产实现，也没有 B 的 `EventSyncService` 具体实现。默认真实模式因此明确显示“真实
设备网络服务尚未装配”，不会伪装搜索或连接成功。

A/B 实现合入后必须执行并归档：

1. 未知 IP 下搜索到正确 `device_id`，重复响应不产生重复设备。
2. 错误 Token 进入认证失败且不无限重试；正确 Token health 200 且身份一致。
3. 默认辅码流持续出帧，切换主码流、切换设备、断线重连和显式停止均正常。
4. 视频播放期间 health 和事件查询正常；任一链路故障不错误关闭另一链路。
5. 退出后无残留扫描 socket、HTTP reply、RTSP 重连定时器或媒体资源。
6. B 的同步服务完成至少一个事件入库，形成“搜索－连接－播放－事件入库”完整 G2 证据。

只有上述真机记录完成后，才能关闭整个第 2 阶段 G2；本报告当前只关闭软件 C 可独立完成的实现项。
