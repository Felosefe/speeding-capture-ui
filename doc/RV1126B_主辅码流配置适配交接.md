# RV1126B 主辅码流配置适配交接

## 1. 交付范围与固定参数

本次交付 Qt 上位机界面、HTTP 客户端、配置控制器和自动化测试。下面的
`/api/v1/config/video-streams` 是**新增接口约定**，并不代表当前板端已提供该接口。
板端实现并完成真机验证后，Qt 中的选择才会实际改变摄像机输出。

| 码流 | RTSP 路径 | 固定编码输出尺寸 | 可选编码 |
| --- | --- | --- | --- |
| 主码流 | `/live/0` | 2560×1440（2K） | `h264` / `h265` |
| 辅码流 | `/live/1` | 1920×1080（1080p） | `h264` / `h265` |

两路编码独立，允许任意组合。切换编码时，输出尺寸保持表中固定值；只调整视频编码输出，
不要同时改变传感器采集、检测/抓拍、OCR、证据图或线位坐标的配置。帧率、码率等参数沿用
板端现有配置，本接口不修改。视频继续通过原 RTSP 地址播放，不增加 codec URL 参数。

板端全新 profile 默认两路 `h264`。升级旧 profile 时保留已有合法编码，并将两路编码输出
尺寸迁移为固定值；Qt 首次读取沿用板端返回的编码，不会因连接设备自动写配置。

## 2. 新增 HTTP 接口

沿用 `/api/v1`、Bearer Token 鉴权和现有 JSON 错误封装。请求、响应均使用 UTF-8 JSON。
HTTP 客户端实现位于 `BoardApiClient`，严格编解码位于 `BoardApiCodec`。

### 读取配置

```http
GET /api/v1/config/video-streams HTTP/1.1
Authorization: Bearer <token>
```

成功返回 HTTP 200：

```json
{
  "api_version": "v1",
  "revision": "video-r17",
  "runtime_revision": "runtime-r42",
  "write_enabled": true,
  "restart_required": false,
  "main": {"width": 2560, "height": 1440, "codec": "h265"},
  "sub": {"width": 1920, "height": 1080, "codec": "h264"}
}
```

所有示例字段均为必填；未知扩展字段被 Qt 忽略。

| 字段 | 类型与语义 |
| --- | --- |
| `api_version` | 字符串，固定为 `v1` |
| `revision` | 非空字符串，已持久化的两路视频配置版本，用于 PUT 并发校验 |
| `runtime_revision` | 非空字符串，运行配置版本，用于现有 runtime/apply 接口；须与其他运行配置写入共享一致的版本机制 |
| `write_enabled` | 布尔值，表示当前用户/设备是否允许写入视频配置 |
| `restart_required` | 布尔值；已保存视频配置尚未在运行编码器生效时为 true；只有运行输出确认使用该配置后才能返回 false |
| `main` / `sub` | 已持久化的视频配置，各包含正整数 `width`、`height` 和小写字符串 `codec` |

GET 返回保存值，不能用 GET 的尺寸冒充正在播放的实际尺寸。Qt 根据视频帧单独显示实际尺寸。
GET 允许读取旧 profile 的其他正整数尺寸，以便迁移；编码只接受 `h264`、`h265`。
缺字段、错误类型、非正整数尺寸或其他编码会被 Qt 判为协议不兼容并禁止编辑。

### 保存配置

```http
PUT /api/v1/config/video-streams HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "expected_revision": "video-r17",
  "main": {"width": 2560, "height": 1440, "codec": "h264"},
  "sub": {"width": 1920, "height": 1080, "codec": "h265"}
}
```

PUT 必须校验写权限、当前 revision、完整两路对象、固定尺寸和编码枚举。
主流必须为 2560×1440，辅流必须为 1920×1080，不接受尺寸自定义或 `H264`、`hevc` 等别名。
板端须原子保存两路配置；任一路无效时两路都不写。并发比较与写入须在同一临界区内完成。
写入失败不能返回成功或使 profile 处于半更新状态。

成功返回 HTTP 200，结构与 GET 完全相同，反映新的保存值及版本。例如：

```json
{
  "api_version": "v1",
  "revision": "video-r18",
  "runtime_revision": "runtime-r43",
  "write_enabled": true,
  "restart_required": true,
  "main": {"width": 2560, "height": 1440, "codec": "h264"},
  "sub": {"width": 1920, "height": 1080, "codec": "h265"}
}
```

PUT 保存后若已完成热应用，允许返回 `restart_required=false`。需要重启/重建编码器时返回
true，并提供可用于下一步运行应用的 `runtime_revision`。保存与生效状态必须分开报告。

### 错误约定

```json
{
  "api_version": "v1",
  "error": {
    "code": "config_revision_conflict",
    "message": "configuration revision changed"
  }
}
```

| HTTP | 建议 `error.code` | Qt 行为 |
| --- | --- | --- |
| 400 | `invalid_video_streams_config` | 提示参数被拒绝，保留编辑值 |
| 401 | `unauthorized` | 提示检查 Token |
| 403 | `config_write_disabled` | 禁止配置操作 |
| 404 / 501 | `video_streams_config_unsupported` | 提示升级板端接口，禁用配置操作；保留视频预览 |
| 409 | `config_revision_conflict` | 重新 GET 更新版本，保留两路编辑值，要求用户检查后重新应用；不自动覆盖 |
| 500 / 503 | `video_streams_config_write_failed` / `video_streams_config_unavailable` | 提示失败；不自动重发 PUT |

Qt 使用状态码与稳定错误类别处理，不直接显示服务端自由文本。

## 3. 复用运行时应用接口

需要应用时，Qt 继续使用仓库已有接口：

```http
POST /api/v1/config/runtime/apply HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "expected_revision": "runtime-r43",
  "scope": "rkipc"
}
```

沿用现有响应字段，PID 是字符串：

```json
{
  "api_version": "v1",
  "runtime_revision": "runtime-r43",
  "state": "applied",
  "restart_scope": "rkipc",
  "old_rkipc_pid": "1403",
  "new_rkipc_pid": "1507"
}
```

板端负责将保存配置应用到实际编码器，并恢复原 RTSP 服务；具体编码器参数键和重建方式
由板端仓库实现确认，本 Qt 仓库不包含可据以指定这些内部实现的代码。
runtime/apply 必须执行版本校验，避免错误应用其他客户端刚写入的运行配置。
若运行应用失败，保留已保存配置并保持 `restart_required=true`，供用户再次应用。
仅成功保存配置不能清除该标志；重启后仍须从持久化 profile 加载相同编码和尺寸。

Qt 保存成功后有三种路径：

1. 不需要重启：直接 GET 确认保存值、运行状态，再重新打开当前预览。
2. 需要重启：POST 一次，再 GET 确认；若 POST 暂时断网，也进入读回确认，不自动重发 POST。
3. POST 明确失败：显示“已保存，待应用”；用户再点应用时，若编辑值未改变，仅重试 POST。

读回立即尝试一次；临时网络错误或仍未生效时，按 1、2、4、8 秒间隔最多再读四次（每次
HTTP 请求仍有自身超时）。只有 GET 两路值与提交目标一致且 `restart_required=false` 才提示
“已生效”。耗尽后提示刷新确认；人工刷新也能确认成功并恢复预览。不通过读回重试执行写操作。

## 4. Qt 交互与兼容性

- 实时预览新增码流控制行，默认辅码流。编码选择框编辑当前所选码流；两路草稿随主辅切换保留。
- “应用码流设置”一次提交两路；目标尺寸只读，旧尺寸也能通过该按钮迁移。连接和切换码流不写配置。
- 正在保存、应用和读回时禁用重复提交及编码编辑；刷新读取板端值并放弃当前设备未提交草稿。
- 切换设备清空草稿和确认目标，旧设备的完成回调与定时重试不能改变新设备状态或触发其写入。
- 预览恢复仅作用于原设备仍被选中、在线且未暂停的情况；不改变用户当前选择的主辅码流。
- “目标码流”显示固定目标尺寸；“实际”来自解码帧，不一致时标记“与目标不符”。等待出帧时不宣称实际尺寸。
- H.264/H.265 解码沿用 Qt Multimedia/FFmpeg，不在客户端转码或通过拉伸画面伪造目标尺寸。
- 旧固件未提供新接口时禁用配置入口，原主辅 RTSP 预览仍可使用。模拟模式的旧设备配置页面不参与真实设备下发。
